0实时监控（一边聊一边看）

把这个一直跑在另一个终端窗口，所有 memory 相关操作都会刷过来：

ssh new 'journalctl -u 3yan-server -f | grep -iE "memory|embedding|profile|summary|rag|deepseek"'

1profile 抽取（最快验收）

耗时 1-2 分钟 依赖 DEEPSEEK_API_KEY 有效 已配置
触发条件：用户每发一条消息 + 距上次抽取 ≥ 5 分钟（Redis NX 节流）

操作步骤

跟小婉聊一句：我家有只猫叫橘子，我是个前端工程师，住在北京
等 5-10 秒（@Async + LLM 调用时间）
查数据库验证 profile_jsonb 是否被填充

验证 SQL

ssh new 'sudo -u postgres psql -d sanyan -c "SELECT user_id, character_id, profile_jsonb FROM memory_profiles;"'
profile_jsonb.events 数组里含 "猫" / "橘子"
profile_jsonb.basic_info.occupation = "前端工程师"
profile_jsonb.basic_info.hometown = "北京"

失败排查

看 log 有没有 ProfileExtract / 节流 关键字
如果一直没记录：DEEPSEEK_API_KEY 是否真的生效（看 log 有没有 4xx）
5 分钟内重发不会再触发（节流），需要等过 5 分钟或者重启清 Redis key

2summary 生成（30 条触发）

耗时 10-30 分钟 依赖 DEEPSEEK_API_KEY + 聊够 30 条消息 需要量
触发条件：自上次摘要以来累积新消息 ≥ SUMMARY_TRIGGER_THRESHOLD (= 30)
第 30 条消息持久化后，SummaryScheduler 异步触发

操作步骤

跟小婉来回聊 30+ 条（你的话 + AI 的话各算一条，大约 15 轮对话）
第 30 条消息落库后等几秒
查 memory_summaries 表

验证 SQL

ssh new 'sudo -u postgres psql -d sanyan -c "SELECT id, user_id, character_id, message_count, LEFT(summary_text, 80) as preview, created_at FROM memory_summaries ORDER BY id DESC LIMIT 3;"'
新增一条 summary 记录
summary_text 是 100-200 字中文纪要
message_count ≈ 30

失败排查

数当前消息数：SELECT count(*) FROM message WHERE user_id = 1;
看 log 关键字：grep "Summary"
如果攒够 30 但没 summary：检查 DeepSeek 4xx / 网络

3RAG 检索（隔天再问旧事）

耗时 当天可观测索引落库，但效果最好隔几天再问 依赖 embedding 服务（已在 old 上跑） + 累积历史 最体现"长期"
触发条件：每 5-10 条消息 → ChunkBuilder 切片 → embedding 服务拿向量 → 存 chat_embeddings
用户新提问时 → embed query → pgvector cosine Top 5 (cos sim > 0.6)

操作步骤 - 第一阶段：累积

持续聊 10+ 条消息（多个话题）
验证 chunks 已索引：
ssh new 'sudo -u postgres psql -d sanyan -c "SELECT id, user_id, array_length(message_ids, 1) as msg_count, LEFT(chunk_text, 60) as preview FROM chat_embeddings ORDER BY id DESC LIMIT 5;"'
有 1+ 条 chat_embeddings 记录
msg_count 在 5-10 之间
preview 是中文聊天内容

操作步骤 - 第二阶段：召回

隔几小时或第二天，问指向之前内容的问题
例：之前提过猫，现在问 上次说的那只猫叫什么来着
看小婉是不是能从历史里捞回名字

查看 RAG 调用日志

ssh new 'journalctl -u 3yan-server -n 200 --no-pager | grep -E "RagSearch|MemoryContext|embed"'

4降级（embedding 服务挂时不影响聊天）

耗时 5 分钟 依赖 主聊天 + embedding 服务都跑着 破坏性测试
验收点：embedding 服务挂掉时，主聊天必须照常工作（RAG 段在 prompt 里直接跳过）

操作步骤

停 embedding 服务（模拟挂掉）：
ssh old 'systemctl stop sanyan-embedding'
用 app 正常跟小婉聊几句
主聊天照常返回（豆包还能调）
log 里看到 Embedding 服务不可用，RAG 降级返回空列表
主线程不抛 BusinessException

恢复 embedding 服务

ssh old 'systemctl start sanyan-embedding'

⚡最短验收路径

顺序动作预期
1 开监控终端（顶部命令） 看到日志在 tail
2 聊一句含个人信息（e.g. "我家有只猫叫橘子"） 10 秒内 log 出现 ProfileExtract
3 查 memory_profiles 表 events 含"橘子"
4 聊够 30 条 memory_summaries 多 1 条
5 查 chat_embeddings 表 看到 chunks 入库
6 隔半天或一天后问"上次说的橘子是什么品种" 小婉答得出（验证 RAG 召回）

📋查询命令小抄

看消息表

ssh new 'sudo -u postgres psql -d sanyan -c "SELECT id, user_id, sender_type, LEFT(content, 40) as preview, created_at FROM message ORDER BY id DESC LIMIT 10;"'

看 profile

ssh new 'sudo -u postgres psql -d sanyan -c "SELECT user_id, jsonb_pretty(profile_jsonb) FROM memory_profiles;"'

看 summary

ssh new 'sudo -u postgres psql -d sanyan -c "SELECT id, message_count, summary_text, created_at FROM memory_summaries ORDER BY id DESC;"'

看 RAG chunks

ssh new 'sudo -u postgres psql -d sanyan -c "SELECT id, user_id, array_length(message_ids, 1) as cnt, LEFT(chunk_text, 80) FROM chat_embeddings ORDER BY id DESC LIMIT 10;"'

看 Redis 队列堆积

ssh new 'redis-cli XLEN sanyan:memory:rag:index-queue'

看 DLQ 日志

ssh new 'journalctl -u 3yan-server | grep RAG_INDEX_DLQ'

embedding 服务健康检查

ssh old 'curl -s http://localhost:8080/actuator/health'

清 profile 节流 key（让 5 分钟节流失效，方便连续测）

ssh new 'redis-cli --scan --pattern "sanyan:memory:profile:throttle:*" | xargs -r redis-cli del'
